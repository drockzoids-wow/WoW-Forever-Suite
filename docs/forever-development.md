Keep globals limited to the declared saved table, slash command registration and necessary compatibility entry points. Avoid collisions with Blizzard or other addons.

## Secure code and combat lockdown

WoW's secure UI protects gameplay actions and selected frames. Ordinary addon code cannot freely cast spells, choose targets or rewrite protected action behavior during combat. A secure action template permits defined actions through its supported attributes and permitted user interaction; it does not grant general automation privileges.

Cosmetic changes still need care when they reach a protected frame or one of its dependencies. Check `InCombatLockdown()` before changing protected anchors, scale, movement, parenting or configuration. Queue the latest requested change and apply it after `PLAYER_REGEN_ENABLED`. A frame can also be forbidden; skip it rather than probing it through repeated errors.

Observe Blizzard behavior with supported hooks and keep module callbacks reversible where possible. Replacing secure functions, altering panel-manager globals or modifying restricted frame scripts can taint Blizzard execution, causing an action to be blocked later. `hooksecurefunc` does not make code in its callback secure. Catching an error with `pcall` does not grant access. The matching [secure template implementation](https://github.com/Gethe/wow-ui-source/blob/e3ecc27b64d30fdc735a3f6579b866858f9f9df1/Interface/AddOns/Blizzard_FrameXML/SecureTemplates.lua) is a reference for supported behavior, not a template to transplant wholesale.

## Secret values and access predicates

Secret values hide information from ordinary addon logic while allowing specified native presentation paths. Check `issecretvalue` or appropriate access predicates before comparing, calculating, formatting, indexing by or exporting a potentially restricted value. Guard each value that an operation uses; guarding one field does not authorize the rest of its record.

Restrictions depend on the API, unit, spell, map and active combat or encounter state. A value readable in town can be restricted later, and individual spells can override general secrecy rules. Check the documented `SecretArguments`, `SecretWhen...`, `Requires...`, `Environment`, `NeverSecret` and method protection markers. UI objects can acquire secret aspects when they display restricted data. A widget accepting a value does not make the value readable again.

For presentation, use the explicitly supported native path. For example, status bars have documented secret argument support; spell and aura duration objects offer native timing paths subject to the receiving widget's access rules. Do not calculate hidden cooldowns by subtracting timestamps or reinterpret a display object as an unrestricted data source.
